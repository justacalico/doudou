# 15.0.0

- Refactor unified audio handler architecture: extract provider-specific logic into separate handler files (lib/services/audio/providers/). Each provider (YouTube Music, SoundCloud, Navidrome/Jellyfin, etc.) now has its own handler class extending BaseProviderHandler. This separates provider logic from core playback, making the codebase more maintainable and easier to extend. The main UnifiedAudioHandler now delegates provider-specific operations (URL resolution, AudioSource creation, completion handling) to these handlers.
- Fix linter errors: correct import paths in provider handlers (use `../../../models/` instead of `../../models/`), add missing `ServerType` import in unified_audio_handler, fix Track constructor calls (remove invalid `artists` parameter), remove unnecessary non-null assertions in YouTube Music handler, and remove unused variable in `_waitForStreamReady`.
- Navidrome/Jellyfin playback: wait for position to advance before setting state to playing (up to 2 seconds) since duration may not be reported immediately. This ensures audio is actually playing before reporting success. If position doesn't advance, retry play() once. Adds debug logs to track position advancement during playback initialization.
- MPV config: fix duplicate `ao=` entries in mpv.conf by removing any existing `ao=` lines (both `ao=pulse` and `ao=alsa`) before adding `ao=pulse`. This prevents conflicts when the config file already contains `ao=alsa` or multiple `ao=` entries. Only Doudou-added audio output comments are removed; user-added options are preserved.
- MPV config: make config temporary - store original content when modifying mpv.conf and restore it when the app closes. This prevents leaving Doudou-specific settings (ao=pulse, cache=no, user-agent, referrer, audio-exclusive) in the user's MPV config file after the app exits. Cleanup is called automatically from AppState.dispose() on desktop platforms.
- Desktop (non-YT providers): fix audio not playing - wait for stream ready (duration > 0) after play() before setting state to playing, similar to YouTube path. This ensures the stream is actually loaded before playback is considered successful.
- Desktop (non-YT providers like Navidrome): fix audio not starting playback - skip waiting for stream ready (Navidrome doesn't report duration immediately), call play() immediately after setAudioSource with simple retry logic, and add debug logs to track playback state.
- Desktop (Linux) non-YT: wait for stream ready (duration > 0) before returning from load and re-apply volume so Navidrome/Jellyfin audio output opens reliably (same pattern as YT path).
- Linux: set MPV ao=pulse in mpv.conf so Navidrome and other non-YouTube providers output audio (use ao=alsa in ~/.config/mpv/mpv.conf if you have no PulseAudio).
- Desktop (Navidrome/Jellyfin etc.): fix playback not starting and progress showing 0:00 by setting state to playing and duration from track metadata after play() succeeds (media_kit may not emit ready→playing on Linux). YT-only logic remains gated to isYouTubeMusic.
- YouTube Music: fix autoplay not advancing to next track (looping same song) by relaxing completion guards: shorter ignore-after-load (5s) and cooldown (3s), trust completion after 5s play, and lower min position so real completions are accepted and queue advances.
